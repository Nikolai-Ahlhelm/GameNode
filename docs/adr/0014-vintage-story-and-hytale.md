# ADR 0014: Vintage Story, Hytale, shared mod management, and console line endings

## Status
Accepted.

## Context
ADR 0013 added Minecraft installation and mod management. Two more games were requested with the same capabilities: Vintage Story and Hytale. Their distribution models differ sharply:

- **Vintage Story** publishes a public JSON index (stable and release-candidate versions, per-platform server archives, MD5 checksums) and a self-contained .NET server. It can be installed like Minecraft.
- **Hytale** server files are only distributed through Hytale's official downloader, which requires an interactive OAuth login with a Hytale account, and the running server then needs its own account authentication. GameNode does not implement account-login flows (compare the SteamCMD anonymous-only rule), so it cannot install Hytale.

## Decision
- **`internal/mods`** is the shared, game-neutral mod archive manager (list, upload, enable/disable by renaming to `*.disabled`, remove). A `Profile` supplies the game's mod directory, accepted extensions, and an optional metadata reader. `internal/minecraft` keeps its public mod API as aliases over a Minecraft profile (`.jar` in `mods`; Fabric/Quilt/NeoForge/Forge metadata). `GET|POST|PATCH|DELETE /servers/{id}/mods` selects the profile from the server's creation-time template (`vintage-story`, `hytale`, Minecraft templates); a server without a recognized template keeps the historical Minecraft behavior. No new permissions or audit actions: `Files.View/Upload/Rename/Delete` and `file.upload/rename/delete`.
- **Vintage Story** (`internal/vintagestory`, installer type `vintagestory`, resolver `vintagestory`): fixed sources `api.vintagestory.at` and `cdn.vintagestory.at` (HTTPS, host allow-list, bounded index and archive); only exact stable (`1.22.7`) and release-candidate (`1.22.0-rc.10`) versions from 1.21.0 up (the oldest version whose configuration keys and runtime were verified). The published MD5 is verified before extraction; extraction reuses the SteamCMD safe extractor with higher, explicit limits (entry count and size). The installed server's `runtimeconfig.json` states the required .NET major version and is checked against `dotnet --list-runtimes`; the wizard also shows an advisory per version. Launch is `dotnet VintagestoryServer.dll --dataPath data --port N` with root-relative paths (so a tenant migration that moves the root keeps working), stopped with the `/stop` console command. Mods are `.zip` archives in `data/Mods`, identified from the root `modinfo.json` with bounded lenient field patterns (the file is not strict JSON). `data/serverconfig.json` is edited by a post-start-only `json-key-values` adapter (26 verified scalar keys common to 1.21.6 and 1.22.7); the port is controlled by the launch argument and deliberately excluded from the adapter. Nested world settings (seed, play style) are not managed.
- **Hytale** (template `hytale`, installer `existing-files`, resolver `java`): adopt-only. The operator downloads the server with Hytale's downloader and GameNode validates `Server/HytaleServer.jar` and `Assets.zip`, then launches `java -Xms -Xmx -jar Server/HytaleServer.jar --assets Assets.zip --bind 0.0.0.0:PORT` directly from the selected folder (UDP port, `/stop`). Adopting needs global `Server.Create` because the folder is an arbitrary host path, like the other adopt flows. Mods are `.jar` or `.zip` archives in `mods`, identified from the documented `manifest.json` (`Group`, `Name`, `Version`, `Description`). **No configuration adapter**: `config.json` key names are undocumented and have changed between early-access builds, and an adapter whose managed keys are missing fails the whole Configuration view. It is deferred until a real file can be verified.
- **Console line endings**: Vintage Story's console only treats CR+LF as Enter, so a bare LF never runs `/stop` and every stop would end in the force-kill timeout (verified live: `/stop` + LF is ignored, `/stop` + CR+LF shuts down cleanly in seconds). Servers therefore carry `console_line_ending` (`lf` default, or `crlf`; migration `035_console_line_ending.sql`, CHECK-constrained). A template launch may declare it; `servers.Server.ConsoleInput` converts line breaks for the stdin stop command and all console input paths (browser WebSocket and the machine-authenticated Node console). An edit request that omits the field keeps the stored value. Existing servers default to `lf`, so nothing changes for them.

## Consequences
Vintage Story installs need outbound access to two hosts and a matching .NET runtime that GameNode does not install; an installation without it stops with `VINTAGESTORY_RUNTIME_MISSING` (files may remain). Linux behaviour of the CR+LF requirement was not tested here (Windows only); CR+LF is sent on both platforms and Linux consoles ignore the extra CR. Hytale remains blocked on a non-login download path; the day Hytale offers one, an installer can follow ADR 0013's pattern.
